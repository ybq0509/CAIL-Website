CAIL CONTENT STUDIO

使用与部署说明

本机编辑服务只在这台电脑运行。保存文章会修改本地内容文件，不会自动提交 Git 或更新正式网站。

开始编辑

  1. 打开内容管理，点击文章旁的“编辑”，或点击“新增文章”。本机出现“登录”按钮时直接点击，不需要密码。
  2. 填写稳定的网址标识、栏目、分类、新闻发布日期和封面。活动日期可独立填写。
  3. 编辑英文标题、摘要和正文，展开简体及繁体栏目补齐翻译。右侧预览可以切换三种语言。
  4. 在正文“添加组件”中选择“图片与图注”；图片和图注可在正文中调整顺序。支持 JPG、PNG、WebP，单张不超过 10 MB。
  5. 点击编辑器顶部“发布”保存到本机。它在本机模式下表示保存本地文件，正式网站不会改变。若修改的是现有文章，使用顶部状态菜单中的发布操作。
  6. 在本机网站检查首页、列表、详情和搜索。保存后页面会自动重新生成。

首页推荐规则

开启“允许首页推荐”后，文章成为首页候选。数字更大的优先级排在前面；相同优先级按新闻发布日期倒序。新闻和活动分别选取，首页默认各显示 3 条，可在“首页显示设置”调整。

旧文章日期

迁移时保留了旧网页的日期，并标记“发布日期待核对”。请核对真正的新闻发布日期后关闭该开关。LEXFLOW 的 2027-02-08 作为活动日期保留，未将它当作新闻发布日期。

归档与下架

归档后文章从首页和列表移除，但旧网址和全站搜索仍保留。下架后不生成详情页，旧网址会返回 404。若只是暂时不在首页展示，关闭首页推荐即可。

保存、审核和上线

本机模式直接读写文件，不启用多人审核。之后部署线上认证服务后，GitHub 模式提供草稿、审核、批准发布流程；要限制谁能批准，需要同时配置仓库分支保护。公开 GitHub 仓库中的草稿分支也可被读取，请勿存放未公开的敏感材料。

重新启动本机后台

cd "/Users/yinboqin/Desktop/CAIL-Website/CAIL-Website-deploy"
npm ci
npm run dev:cms

打开 http://localhost:8767/admin/。在终端按 Ctrl+C 可关闭网站预览和文件编辑代理。

之后部署到正式网站

完整步骤见仓库的 docs/CMS.md。先在已有服务器部署 auth/ 中的认证服务，创建 GitHub OAuth App 并配置服务端凭据；把认证 URL 写入 content/settings.json 的 authUrl。网站仓库提交后，在 GitHub 的 Settings → Pages 把发布源设为 GitHub Actions，由工作流构建并发布 _site。请勿再直接上传整个仓库。

本页不包含任何密码、令牌或私钥。认证服务尚未部署时，正式站的编辑入口会提示需要配置。
